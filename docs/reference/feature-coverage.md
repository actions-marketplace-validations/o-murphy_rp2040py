# What the emulated RP2040 implements, and what it does not

One place to see, block by block: is it modelled, is it in the C++ core, was it read against the datasheet, what is **missing**, and **when** each missing thing is to be done. The *why* and the evidence live in the records (every row links one); this file is the checklist that tells you where to work next.

**Rules of upkeep.** (1) A change that adds, fixes or removes behaviour of a block updates its rows here in the same commit. (2) A missing feature is listed here **and** in 0098's backlog table; it is implemented only on an explicit go-ahead (CLAUDE.md, "Document vs. implement"). (3) A row says *what* is missing in the datasheet's words, never "TODO".

Legend: `[x]` implemented and tested; `[~]` partly (the text says which part); `[ ]` not implemented. **When**: *next* = the agreed order (record 0096 / 0098), *with X* = done together with another item, *go-ahead* = a backlog feature that waits for the maintainer's explicit word, *needs X* = blocked by a prerequisite.
